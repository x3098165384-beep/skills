# VS Code 准备与排查

仅在首次使用 CodeTour，或发生安装、命令、定位、显示问题时读取。步骤依据当前电脑实际情况执行；不切换配置、重装插件或改设置来代替诊断。

## 插件与当前配置

CodeTour 扩展 ID 是 `vsls-contrib.codetour`。检查当前编辑器、当前工作区和当前配置名称；VS Code 的不同配置可以拥有不同插件列表。

若可用，先通过窗口信息、VS Code 的配置入口或本地配置记录确认当前配置，再查询该配置的插件列表。CLI 的 `--profile` 参数只使用已经确认的名称；猜名称可能创建新配置。扩展目录存在或默认配置列出了插件，不能证明当前窗口已安装并加载。

安装、启用或调整设置按用户本次请求和环境规则执行。安装时指定已确认的配置；之后检查该配置的插件列表，以及是否需要重新加载窗口。日志检查只取 CodeTour 的加载或报错记录，避免打印整个进程树或无关插件日志。

## 打开讲解

- 用 VS Code 打开讲解对应的项目根目录，使 `file` 的相对路径有正确起点。
- 在命令面板查找 CodeTour。可使用当前插件提供的 Start Tour 或 Open Tour File 命令。
- 在本次验证的版本中，Start Tour 只有发现讲解后才显示。找不到命令时，先核对配置和插件状态，再读安装版本的 `package.json` 核对实际命令及显示条件。
- 更新讲解后若仍显示旧内容，结束当前讲解，再启动同名讲解。保留原文件名和标题，减少重复条目。

## 框下有空白，文字仍有上下滚动条

CodeTour 使用 VS Code 的评论框。外框高度和正文高度限制是不同设置；拉高外框可能仍受评论正文上限限制。

本次核对的 VS Code 支持布尔设置 `comments.maxHeight`：默认启用，控制评论正文滚动还是展开。需要展开时，在设置中搜索 `@id:comments.maxHeight`，关闭该选项，再重新打开讲解。它影响同类评论框，不仅是 CodeTour。

这是按需调整项，不在生成教材时自动修改。其他版本先核对当前设置是否仍存在。

## 讲解挡住了正在说的代码

把步骤定位到相关代码段的最后一行，让评论框在代码下方。使用 `pattern` 时，CodeTour 按匹配起点确定行；匹配整段代码可能又把评论挂回首行。

单行文字重复时，用 JavaScript 正则的上下文条件使目标唯一，不改源码来制造定位标记。检查工具必须使用 JavaScript 正则；其他语言的正则通过不等于 CodeTour 能匹配。

参考当前安装插件的 schema 和实现确认 `line`、`selection`、`pattern` 的优先级。优先保留唯一的内容定位；采用固定行号时，源码变化后重新核对。
