# 用 CodeTour 学项目代码

仅在用户明确调用 `$teach-with-codetour` 时启动。

交付独立的 `.tours/*.tour` 文件，让读者在对应代码旁看懂：这一段要完成什么、怎样执行、变量怎样变化、最终得到什么结果。教学范围以用户当前要理解的代码或功能为准。

## 先确定要讲的完整过程

- 读取当前源码及理解这段行为确实需要的调用处，区分已实现行为与举例假设。已有证据足够时直接复用；范围不明确且无法从上下文判断时，只询问需要学习的代码范围。
- 先说明整段如何完成实际工作，再解释其中的语法。按完整代码段组织步骤，例如继续旧安排、检查候选、返回结果；不规定步数。把同一段的说明与执行例子放在一起，避免在同一位置反复翻页。
- 中文对象与代码名称同时出现，例如“暂选点 `selected`”。说明每个循环数的是什么、每个判断决定什么，以及 `continue`、`return` 对后续执行的影响。
- 首次编写导览，或读者仍不清楚变量如何变化时，读取 [教学示例](references/teaching-example.md)，按其完整执行方式讲解；保留真实对象和变量，替换为当前项目的情境。

## 先举例，再对照代码

每个代码段先给出具体情境和要解决的问题，然后对照代码解释，最后说明结果。

涉及循环、随机或状态变化时，选择一组明确输入，从头执行到底。表格列出本轮对象、关键变量、条件或随机值、执行动作和留下的结果；列数由当前问题决定。随机数字明确标为一种可能的结果，不暗示每次相同。

讲解同时包含两层内容：

- 具体例子：这次怎样执行，例如“本次抽到0，暂选点从点2换成点4”。
- 一般规则：哪些值由配置或实际候选数决定，换成1个或更多对象时会怎样。区分某轮替换机会与最终选中机会。

只有需要解释所用语法时，才拆解运算符和循环各部分。明确语法本身的意义与项目代码赋予的用途，例如整数0不会自动表示“专属点”。

用户追问时先在聊天中直接解释。请求同步教材时，更新对应代码段的原说明和例子；增加步骤须有不同代码段或独立学习目标，不把每次追问都追加成一页。

## 编写独立讲解文件

- 默认只创建或更新讲解文件。源代码、配置、插件设置等修改遵守本次授权和项目规则；学习代码本身不授权修改业务逻辑。
- 步骤的 `file` 使用项目根目录相对路径。优先用唯一匹配的 `pattern` 定位，表达式适用于 JavaScript `RegExp`，避免仅靠易变行号。
- 把说明定位到要看的代码段末行，使整段代码留在评论框上方。匹配多行时 CodeTour 使用匹配起点；可用后续代码限定匹配条件，只匹配末行。首次使用时核对插件当前实现，不把这一做法当作永久 API。
- 描述用段落、行内代码和必要的表格。只读讲解不加入 `commands` 或可执行命令链接；整段代码直接看源码，不在评论里重复。CodeTour 的围栏代码块可能提供插入代码操作，使用前先确认当前插件行为与用户意图。
- 首次在该环境使用，或出现命令缺失、代码被遮挡、正文滚动等显示问题时，读取 [VS Code 准备与排查](references/vscode-setup.md)。只在需要时诊断，不在每次写教材时重复检查环境。

## 验证与交付

检查工具使用 Node.js。执行时显式给出项目根目录与本次讲解文件：

```text
node scripts/check-tour.mjs --root PROJECT_ROOT .tours/FILE.tour
```

这里的脚本路径相对于本技能目录；实际调用使用脚本绝对路径，并替换项目与讲解文件位置。它只读文件，检查 JSON、代码文件、有效位置和定位表达式，并提醒同一位置的重复步骤。它不评判教学效果，也不证明项目编译或运行正确。

随后人工复读，确认：

- 每个代码段先说明要完成的实际工作，中文名称能对应到可见代码。
- 示例的输入、条件、变量变化和最后结果相互一致，未省略读者正在追问的关键过程。
- 同一段代码的说明已经合并，表格服务于执行过程，没有用增加页数代替解释。
- 相关源码未被本次教学任务修改。报告实际执行的检查，不把文件定位检查描述为显示效果验证。

交付时给出讲解文件、打开方式和实际修改范围。界面效果未检查时，由用户在 VS Code 打开确认；不为阅读讲解自动运行游戏、编译或操作项目编辑器。
