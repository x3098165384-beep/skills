# 示例：先讲清代码，再完整执行一次

先解释可见表达式及其执行条件，再用具体输入把过程串起来。不能默认读者已经知道每句含义，也不能用例子中的跑步项、演员位置等情境代替对表达式的说明。

## 先把三句代码拆开说明

```csharp
var action = actions[_step];
_hasPath = action.path != null;
if (_hasPath && !PreparePath(action)) return false;
```

`actions` 是这里被索引的集合，`_step` 是本次使用的索引。`actions[_step]` 用方括号按索引取出一项。`var action` 声明局部变量 `action`，类型由编译器根据右边的表达式推断；`=` 把取到的结果赋给这个变量，后面的代码通过 `action` 使用当前项。

`action.path` 取当前项 `action` 的 `path` 成员。`!= null` 将它与 `null` 作不相等比较，得到 `true` 或 `false`。`=` 把这个判断结果写进 `_hasPath`，所以 `_hasPath` 记录的是本次路径比较的结果；这句没有检查路径里的点是否有效。

下一句的 `if (...)` 根据括号里的布尔结果决定是否执行 `return false`。先读左边的 `_hasPath`；`&&` 要求左右都为 `true`。如果 `_hasPath` 已经是 `false`，整体不可能成立，右边的 `PreparePath(action)` 就不会调用。

左边为 `true` 时，调用 `PreparePath(action)`，把当前项 `action` 传进去。前面的 `!` 对这个调用的返回值取反：返回 `true` 就变成 `false`，返回 `false` 就变成 `true`。这里只能确定该调用怎样影响当前判断，方法内部如何准备路径要读取它的定义。

因此，只有 `_hasPath` 为 `true` 且 `PreparePath(action)` 返回 `false` 时，才执行 `return false`，立即结束当前方法。没有路径时跳过准备调用并继续后面的代码；调用返回 `true` 时也继续。调用者如何处理返回的 `false`，需要对照调用处说明。

## 再代入输入执行

- 假设 `action.path` 是空引用：比较得到 `false`，写入 `_hasPath`；`&&` 左边为 `false`，不调用 `PreparePath`，继续后面的代码。
- 另一个情境，假设路径对象存在，且 `PreparePath(action)` 返回 `true`：`_hasPath` 为 `true`，`!true` 为 `false`，整个条件为 `false`，继续。
- 再假设路径对象存在，但调用返回 `false`：`!false` 为 `true`，左右都为 `true`，执行 `return false`，当前方法不再执行后面的语句。

这些情境中的对象和返回值是明确假设，不表示已经观察到项目当前就是这个状态。逐句说明应在不依赖上述例子的情况下仍然成立。

## 较长循环也先说明代码

下面的点位数量、名字和随机数字都是讲解情境，不是技能固定的数据。实际生成讲解时先读取完整循环及筛选条件，逐句解释真实表达式；下面的概括不代替对实际条件和循环各部分的说明。

### 用一句话说明用途

假设艾琳娜已经决定去工作，这次需要重新选地点，四个专属工作点都可用。这个循环逐个检查场景里的点，只让本组里她能用的点参加抽签，最后在 `selected` 中留下一个结果。

代码段连起来是：

1. `var point = points[i]`：从列表取出当前点。
2. 两个 `if`：跳过空项、其他组的点，以及她不能用的点。`continue` 只跳到下一项，不结束整个找点方法。
3. `count++`：已经遇到的可用点数量加1。
4. 还没有结果时，直接记下当前点；已有结果时，根据 `Random.Range(0, count) == 0` 决定是否执行 `selected = point`，用新点替换旧结果。

整个循环结束，才得到最后的暂选结果。它本身没有移动角色。

### 代码讲清后，完整执行一次

开始时 `selected = null`，`count = 0`。假设按点1、点2、点3、点4检查，下面是一组可能抽到的数字：

| 正在检查 | 加 1 后的 `count` | 本次动作 | `selected` 留下谁 |
| --- | --- | --- | --- |
| 点1 | 1 | 结果还为空，直接记下点1，不抽签 | 点1 |
| 点2 | 2 | 抽到 0，换成点2 | 点2 |
| 点3 | 3 | 抽到 2，不替换 | 点2 |
| 点4 | 4 | 抽到 0，换成点4 | 点4 |

随机范围由本轮 `count` 决定：检查点2时可能得到 0、1；点3时可能得到 0、1、2；点4时可能得到 0、1、2、3。表中的数字只是这次例子的一组结果。

变化是：**没选 → 点1 → 点2 → 仍是点2 → 点4**。

本次最终选中点4。最后一次若抽到1、2或3，就会保留点2。随机数字只决定是否替换，并不对应工作点编号。

### 最后补一般规则

- 只有1个可用点，直接选它；不可用点被跳过，不计入 `count`。
- 四个可用点，最终各有1/4机会；这与本次恰好抽中点4是两件事。
- 两层循环分别说明各自管什么：`pass` 是专属、公共两轮检查；`i` 遍历列表；`count` 数本组可用点。`pass < 2` 没有限制最多两个点。
- 若代码先复用有效预留点或当前点，应先讲这一分支；已经返回旧点时，不会进入随机循环。

首次解释实际 `for` 时，说明初始化只执行一次、每轮前检查条件、每轮后递增，以及本句中的变量各自控制什么；后续沿用已经讲清的语法。说明“索引 0 对应专属点检查”来自循环内部的筛选规则，不是 `for` 语法自带含义。
