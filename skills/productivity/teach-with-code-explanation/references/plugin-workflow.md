# 与行内代码讲解插件协作

生成、更新或检查讲解时读取本文件；出现定位或显示问题时按最后一节区分原因。

## 确定两个目录

代码项目是读者要理解的源码所在目录，也是引用路径的起点。插件工程是提供格式约定、生成工具和读取实现的 `code-explanation-extension`，两者不必相同。

本机插件工程位于 `F:/Sync/MyProjects/code-explanation-extension`。使用前确认它的 `package.json`、`.scratch/reading-experience/explanation-format.md` 和 `dist/explanation.js` 实际存在。其他环境从用户指定位置或已知项目记录查找；不能确定时只询问插件工程位置，不猜测另一套格式。缺少构建产物时说明需要在插件工程构建，不在源码项目安装依赖或修改配置。

生成前必读插件工程的 `.scratch/reading-experience/explanation-format.md`；选择普通或 diff 的行为边界见该文件链接的规格及旧格式代码检查规则。需要完整例子时读取同目录 `explanation.example.json`，JavaScript 格式摘要例子是 `explanation-formatting.example.json`。示例中的提交与摘要属于示例背景，不能抄到当前项目。

本技能不复制一份格式定义。格式变化后按实际约定和解析器处理，解析器拒绝的字段不能靠说明文字绕过。

## 确定讲解输出位置

使用代码项目已保存的 `codeExplanation.directory` 设置，目录相对该项目；未设置时使用 `.code-explanations/`。先读取相关 `.code-workspace` 设置与项目 `.vscode/settings.json`，有可用的已授权 VS Code 配置读取接口时以窗口实际配置为准。项目文件不能证明用户配置、配置文件选择或未保存设置，只有磁盘访问时交付中写明读取了哪些项目设置及采用的目录；遇到无法确定的已有目录选择时再说明具体分歧。

新文件使用有意义的 `.json` 文件名，写入前检查冲突；更新同一讲解保留位置及稳定标识。讲解保留 `version: 2`、标题、可选简介、代码引用和有序步骤，每步含标题及 Markdown 正文。原始源码不额外复制进配套文件。手动打开其他位置的讲解仍明确其代码所属项目，不按讲解位置推断代码根目录。

## 从实际代码生成引用

在代码项目目录执行插件工具，首尾行包含完整相关代码段：

```text
node "EXTENSION_ROOT/tools/code-reference.cjs" "src/example.js" 4 8
```

输出提供当前文件引用与目标，包含完整文本摘要；支持的 JavaScript 还会生成可选格式摘要。外部工具已经取得真实编辑器文本时，可把该文本作为标准输入，加 `--stdin`，全过程不落盘保存源码。命令中的路径和范围必须替换为本次实际文件。

按文件约定把引用放进顶层 `sources`，把稳定步骤标识、引用名称及目标放进 `steps`，步骤正文放进 `body` 字符串。用 JSON 序列化正确转义引号、反斜杠和换行；读取后的正文仍是 Markdown。已有讲解先读取原有标识，再更新相应步骤。插件按全文及范围摘要核对内容，当前文件变动后仅在同文件中唯一匹配时重新定位；不要用正则或只改行号替代对应检查。

生成 JavaScript 格式摘要不表示任意格式化都安全：完整文件须可解析，代码符号、字面值、注释及换行保持对应，才允许符号之间的水平空白变化。其他代码也变动时仍需重新理解。摘要不保存源码，也不证明依赖的方法或业务说明仍然正确。

## 固定版本和 diff

- 普通历史步骤使用 `git` 引用，记录完整提交标识。即使提交等于当前 HEAD，也从该提交读取。
- 两个提交比较使用 `comparison: "commits"`。两侧都按各自提交和明确路径读取，同一仓库中路径可以不同。目标可在单侧或双侧；缺失侧只有确认相应提交不存在该文件时才写 `exists: false`，不设置目标。
- 未提交比较使用 `comparison: "working-tree"`。左侧是生成时的完整 HEAD，右侧是当前编辑器内容，合并已暂存、未暂存及未保存修改；HEAD 改变后需重新核对并更新讲解。

Git 文本可通过本地 `git show <完整提交>:<仓库内路径>` 读取，再送入 `code-reference.cjs --stdin` 计算摘要与范围。工具输出的当前引用要按文件约定改成 Git 引用，补上真实提交，移除引用与目标上的 `formattingSha256`；Git 始终严格检查原文。项目子目录与仓库根目录不同时，先换算仓库内路径。

不为阅读历史版本检出文件、切换分支、提交或改动暂存区。整个文件不存在与存在的空文件分别处理；无法读取提交不能写成成功的空白侧。

## 检查本次文件

```text
node "SKILL_ROOT/scripts/check-explanation.mjs" --root "PROJECT_ROOT" --extension-root "EXTENSION_ROOT" "LECTURE.json"
```

相对的讲解文件位置按代码项目解析，绝对路径可指向项目外。脚本只检查明确指定的 `.json`，不扫描项目文档。插件正式 `parseExplanation` 检查版本、重复字段及完整结构，`checkTarget`、`normalizeText` 和 `sha256` 处理代码对应；脚本不维护另一份格式或摘要算法。

默认对当前源码只检查磁盘，成功信息会注明没有读取编辑器未保存内容。外部 harness 能取得真实文档时，使用 `--workspace-stdin`，向标准输入提供 JSON 对象：键是项目相对路径，值是该文档的完整当前文本，例如 `{"src/example.js":"实际取得的文本"}`。没有提供的引用仍读磁盘，Git 引用始终读 Git。标准输入仅用于本次检查，不写文件；示例中的文字不能当作真实编辑器内容。

脚本复用插件的 `parseExplanation` 和 `checkTarget`，并只读确认路径、Git 对象、文件存在状态、整文件摘要及 HEAD。它无法确认标准输入的来源，不能宣称已连接编辑器；更不能据此声称真实行内 Markdown、diff 位置或教学效果已经通过。

## 一次性转换旧讲解

仅转换本次明确指定的旧文件，先读取真实结构、适用项目规则和原有版本记录。保留原文件，按项目讲解目录检查新文件名冲突；不在插件中加入旧格式读取、导入按钮或自动转换流程。

将旧讲解标题、第一步前的简介及按出现顺序排列的步骤转为显式 JSON 字段，只把外层版本改为 `2`。保留讲解与步骤 `id`、标题、解码后的正文、引用名称、路径、提交、范围和摘要。正文只做 JSON 必需的转义，不顺手改写文字或重算摘要。

逐项比较旧、新内容后调用正式新解析器及检查脚本，记录输入输出位置、文件哈希、结构与逐步代码对应结果。代码已失效就报告具体步骤，不更新摘要制造通过。文件位置改变不承诺自动继承旧进度；新 JSON 主动打开后的保存与恢复由新流程管理。一次性转换使用所需旧版本解析信息，不保留为正常生成服务。

## 在 VS Code 阅读与排查

插件 ID 为 `XGH.code-explanation-extension`，中文名称是“行内代码讲解”。使用前按实际窗口和配置确认是否加载，扩展目录存在不能证明当前窗口已启用；安装、启用和重载依照当前授权执行。

1. 打开代码项目；多根目录时明确选择讲解对应的项目，不按讲解所在位置猜测。
2. 点击左侧“行内代码讲解”图标，从项目列表选择讲解；其他位置执行“行内代码讲解：打开讲解”并选择已保存的 `.json`。展开只列步骤，点击标题恢复进度，点击步骤直接跳转。
3. 使用上一步、下一步或步骤列表；普通与 diff 可混合，双侧目标突出两侧，正文只显示一处。
4. agent 保存有效 JSON 后自动更新，重排保留步骤标识；步骤被删或讲解标识改变时回第一步。新文件无效时保留上次成功内容，并继续检查源码。代码块可以直接拖选复制，也可使用整块复制；复制正文中的原文，不混入行号或说明。
5. “查看正文”打开排版后的完整讲解并定位当前步骤。对应失败时移除整步行内正文及高亮，仍可查看正文；正在使用旧内容时明确标明“上一次成功加载的讲解”。
6. 主动停止后正文与导航清除，代码页和进度保留；再次主动选择讲解、最近记录或继续入口恢复有效步骤，启动编辑器和刷新列表不会自动开始。

定位失败先读完整提示，核对实际项目、路径、版本、未保存文本、目标摘要与 HEAD；不要为了让检查通过保存用户源码或修改源码标记。状态栏仍显示“正在读取”时，编号不代表新正文已经显示完成。

显示或滚动问题先核对当前插件与 VS Code 的实际表现，不自动改全局评论设置。需要复验插件显示能力时，读取插件工程 `docs/background-verification.md`，复用独立桌面、配置、扩展目录和演示仓库；不向用户桌面发送输入或激活窗口。本次没有运行的显示场景明确写未验证。
