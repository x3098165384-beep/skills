# Teach with Code Explanation

仅在用户明确调用 `$teach-with-code-explanation` 时启动。外部 agent 读取真实代码并编写 `.md`，VS Code 的“行内代码讲解”插件负责校验、定位、显示和导航。

让读者在对应代码旁看懂：这一段要完成什么、怎样执行、变量怎样变化、最终得到什么结果。教学范围以用户当前要理解的代码或功能为准，普通脚本不要求先产生修改。

## 先确定要讲的完整过程

- 读取当前源码及理解这段行为确实需要的调用处，区分已实现行为与举例假设。已有证据足够时直接复用；范围不明确且无法从上下文判断时，只询问需要学习的代码范围。
- 先说明整段如何完成实际工作，再解释其中的语法。按完整代码段组织步骤，把同一段的说明与执行例子放在一起，不规定步数。
- 中文对象与代码名称同时出现，例如“暂选点 `selected`”。说明每个循环数的是什么、每个判断决定什么，以及 `continue`、`return` 对后续执行的影响。
- 首次编写讲解，或读者仍不清楚变量如何变化时，读取[教学示例](references/teaching-example.md)，按其完整执行方式讲解；保留真实对象和变量，替换为当前项目的情境。

## 先举例，再对照代码

每个代码段先给出具体情境和要解决的问题，然后对照代码解释，最后说明结果。涉及循环、随机或状态变化时，选择一组明确输入，从头执行到底。

用段落、列表和少量行内代码讲清过程。逐轮比较确实更清楚时再用表格，只保留本次理解需要的列，避免宽表格和每步重复的固定栏目。随机数字明确标为一种可能的结果，不暗示每次相同。

讲解同时说明具体例子和一般规则：本次哪些变量改变、最终留下什么；哪些值由配置或实际候选数决定，换成一个或更多对象会怎样。区分某轮替换机会与最终选中机会。

只有需要解释所用语法时，才拆解运算符和循环各部分。明确语法本身的意义与项目代码赋予的用途，例如整数 0 不会自动表示“专属点”。讲 diff 时分别说明改前行为、改后行为和修改原因，例子使用相应版本的代码。

用户追问时先在聊天中直接解释。请求同步教材时，更新对应代码段的原说明和例子；增加步骤须有不同代码段或独立学习目标，不把每次追问都追加成一页。

## 生成或更新讲解

编写前读取[插件协作方式](references/plugin-workflow.md)，再读取其中指向的插件文件约定。格式、摘要和代码对应检查以插件当前实现为准，检查脚本直接复用其解析器和定位函数。

- 默认只创建或更新讲解文件，沿用项目已有位置；没有约定时使用 `docs/explanations/<主题>.md`。讲解可在项目外，代码路径始终相对选定的代码项目根目录。
- 先确定每步使用当前文件、固定 Git 提交，还是最近提交与当前内容的 diff；引用、完整提交标识、存在状态、行号及摘要全部来自实际内容。
- 目标使用完整相关代码段的起止行和摘要，交给插件突出显示。单侧 diff 也保留完整比较；双侧目标均需有效，正文由插件显示一处。代码就地阅读，只在正文引用理解所需的小片段。
- 新讲解及新步骤生成新 `id`；更新、改标题或重排已有步骤保留原 `id`。源码变动时重新读取并核对说明，再更新引用与目标，不能仅重算摘要掩盖过期解释。
- 源码按编辑器当前内容理解。能通过已授权的工具取得真实未保存文本时，用该文本生成摘要；只有磁盘访问时如实说明，不能假定磁盘就是编辑器当前内容，也不替用户保存源码。
- JavaScript 需要允许已确认的空格、Tab 和缩进变化时，用插件工具生成可选格式摘要；其他语言及固定 Git 按原文检查。能定位不等于业务含义仍正确。

插件只消费独立 Markdown，正文代码块仅用于阅读，普通链接不授予执行命令的权限。教学任务不授权修改业务逻辑、安装或重载插件、改编辑器设置或运行项目。

## 检查与交付

使用 Node.js，显式给出代码项目、插件工程和本次讲解文件。脚本路径相对本技能，实际执行使用绝对路径：

```text
node "scripts/check-explanation.mjs" --root "PROJECT_ROOT" --extension-root "EXTENSION_ROOT" "docs/explanations/FILE.md"
```

脚本只读指定文件，复用插件规则检查结构、实际 Git 内容、HEAD 基准、存在状态和目标，并提示同一版本同一范围的重复步骤。默认当前源码来自磁盘；`--workspace-stdin` 仅在外部工具已取得真实编辑器文本时使用，传入方式见协作参考。插件仍会在实际打开及内容变化时重新检查。

随后复读正文，确认输入、每次判断、变量变化和结果相互一致，同一代码段的说明已合并，中文名称能对应到可见代码。检查本次只改了授权范围内的文件。

交付讲解路径、适用的项目与版本、实际检查结果及“行内代码讲解：打开讲解”的打开方式。保存有效讲解后，插件自动更新并按步骤 `id` 保留位置；下次主动打开恢复进度，停止后保留代码页。

文件检查不证明教学效果、界面显示或项目运行正确。需要界面验证时，沿用已授权的独立后台 VS Code 方式；操作用户窗口须有明确授权。不为了生成教材自动启动窗口或要求重复手测已覆盖场景。
