## What it does

配合“行内代码讲解”插件，在 VS Code 的真实代码及 diff 旁阅读独立 Markdown。每个代码段结合完整输入、执行过程、变量变化和结果讲清实际工作，默认只修改讲解文件。

## When to reach for it

手动输入 `$teach-with-code-explanation`，并说明要学习的代码或功能。这个技能关闭自动选择，只有用户主动调用后才启动。

- 想看懂当前项目的一段代码、循环或状态变化：使用这个技能。
- 想围绕一个主题持续学习并保留学习记录：使用 [teach](https://github.com/x3098165384-beep/skills/blob/codex/skills/productivity/teach/SKILL.md)。

## Prerequisites

需要可读取的项目源码、Node.js，以及 `code-explanation-extension` 插件工程的文件约定和构建产物。查看讲解使用 VS Code 中的“行内代码讲解”扩展，ID 是 `XGH.code-explanation-extension`。讲解沿用项目现有位置，没有约定时写入 `docs/explanations/`；代码路径始终相对所选代码项目。

源码项目和插件工程可以不同。安装扩展、改设置、重载或操作窗口遵守当前授权，生成讲解不会自动进行这些操作。

## 完整执行例子

先说明这段代码要完成什么，再选一组具体输入，从头执行到最后结果。段落和列表能说清时直接使用；逐轮比较更清楚时才用简短表格。随机数字标明是一种可能结果。同一段的说明与例子放在一起，后续追问先直接解释，需要更新教材时修改原说明。

普通脚本、固定历史和真实 diff 可以放在同一讲解中。引用与目标来自实际内容，更新或重排保留步骤标识，保存后由插件自动更新；停止后保留代码页，下次主动打开恢复进度。

## Common questions

**怎样在 VS Code 打开？**

先打开代码项目，再执行“行内代码讲解：打开讲解”，选择已保存的 `.md`。多个项目根目录时明确选择代码对应的项目，讲解本身可以放在其他位置。

**会保存源码副本吗？未保存内容怎么办？**

只保存讲解正文与定位信息，引用已有文件或 Git 内容。能取得真实编辑器文本时，外部工具把文本直接送入生成及检查脚本的标准输入；只有磁盘访问时明确说明，不替用户保存源码。插件打开时仍对照实际编辑器内容检查，不能恢复已经丢失的未提交代码。

**空格变化会让讲解失效吗？**

带格式摘要的当前 JavaScript 文件允许已经确认的空格、Tab 与缩进变化；其他语言和固定 Git 严格核对原文。没有唯一对应位置或代码内容已经变动时，清除行内正文并提供 Markdown 正文。文本对应也不表示整份业务说明已经重新核对。

**还要重复手动测试吗？**

文件检查直接复用插件的解析和定位规则，区分磁盘与外部提供的当前文本；它不能证明界面显示或教学效果。确需验证界面时，复用已有的独立后台 VS Code 方式，不抢夺当前桌面控制权，不要求重复手测已覆盖场景。学习例子的准确性仍需复读。

## It's working if

- 用插件打开 Markdown 后，正文和高亮对应正确代码版本与范围，diff 左右侧没有混用。
- 能按给定输入逐轮追踪变量，并算出说明中的最终结果。
- 同一段代码的说明和例子集中在一起，追问后不会不断增加重复步骤。
- 只新增或更新了讲解文件，学习过程没有改动项目业务逻辑。

## Where it fits

这是手动调用的独立技能，面向当前项目的代码阅读与修改讲解，位置为 `skills/productivity/teach-with-code-explanation/`。[teach](https://github.com/x3098165384-beep/skills/blob/codex/skills/productivity/teach/SKILL.md) 负责跨多次会话的主题学习；不确定该用哪个技能时，可通过 [ask-matt](https://github.com/x3098165384-beep/skills/blob/codex/skills/engineering/ask-matt/SKILL.md) 选择。
